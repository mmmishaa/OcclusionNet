# Датасет

Сборка собственного датасета из чужих под **мультилейбл-классификацию помех**: капли,
грязь, блики, туман, снегопад, смаз и так далее. Источники приземляются как есть, анализ
идёт по манифестам, картинки перекодируются один раз по рецепту.

| файл | что это |
|---|---|
| [taxonomy.yaml](taxonomy.yaml) | схема меток |
| [sources.yaml](sources.yaml) | реестр источников и правила разметки |
| [CANDIDATES.md](CANDIDATES.md) | обзор публичных датасетов по типам помех |
| [recipe.example.yaml](recipe.example.yaml) | параметры сборки |
| [land.py](land.py) | стадия land: каталог с кадрами → манифест |

Грабли и объяснения решений — в [INSIGHTS.md](INSIGHTS.md).

## Принцип

Первичный артефакт — не картинки, а **манифест**: parquet, одна строка на кадр. Все
вопросы «сколько у нас ночного снега», «какие разрешения», «где дубли» решаются запросом
к нескольким миллионам строк за секунды, без единого обращения к пикселям. Картинки
читаются ровно два раза: при заезде и при сборке.

Отсюда три зоны в бакете `<bucket>-datasets`:

```
raw/<source>/<snapshot>/           как скачано, побайтово, иммутабельно
manifest/<source>/<snapshot>.parquet   одна строка на кадр
curated/<name>/<version>/
    shards/{train,val,test}-{00000..}.tar
    manifest.parquet
    recipe.yaml
    SOURCES.md
```

`raw` живёт в ледяном хранилище (0,64 ₽/ГБ·мес), `curated` — в стандартном. Пересборка
датасета читает `raw` внутри облака, то есть трафик бесплатный, платятся только
GET-операции.

## Стадии

| Стадия | Вход | Выход | Когда гоняется |
|---|---|---|---|
| `land` | первоисточник | `raw/` + `manifest/` | один раз на источник |
| `analyze` | `manifest/` | решения в `recipe.yaml` | сколько угодно, дёшево |
| `build` | `raw/` + `recipe.yaml` | `curated/` | на каждую версию датасета |
| `register` | `curated/` | версия в ClearML Data | вместе с `build` |

Заезд и инвентаризация делаются одним проходом: байты и так текут через ВМ, метаданные
и дешёвые метрики считаются на лету. Перекодирования на этой стадии **нет** — иначе
исходник потерян и решения по качеству придётся принимать вслепую, до анализа.

## Заезд в облаке

Локально ничего не качается. Источник приезжает на временную ВМ в Yandex Cloud,
инвентаризация идёт там же, обратно возвращается только манифест — parquet на единицы
мегабайт. Машина описана в [`infra/data.tofu`](../infra/data.tofu) и живёт ровно столько,
сколько идёт заезд.

```bash
cd infra
export YC_TOKEN=$(yc iam create-token)
tofu apply -var enable_data_vm=true      # ~2 минуты
eval "$(tofu output -raw data_vm_ssh)"
```

На машине уже стоят зависимости, настроен `s3cmd` и в `$DATASETS_BUCKET` лежит имя
бакета. Признак готовности cloud-init — файл `/var/lib/data-vm-ready`.

```bash
# код заезда — с локальной машины на ВМ
rsync -av data/ ubuntu@<ip>:~/work/data/

# на ВМ: источник, инвентаризация, сырьё в бакет
cd ~/work
aria2c -x8 <ссылка на источник> -d raw/
unzip -q raw/*.zip -d raw/evocargo/
python -m data.land evocargo_raindrops --root raw/evocargo --out manifest/evocargo.parquet
s3cmd put --recursive raw/evocargo/ s3://$DATASETS_BUCKET/raw/evocargo_raindrops/
s3cmd put manifest/evocargo.parquet s3://$DATASETS_BUCKET/manifest/
```

```bash
# обратно к себе — только манифест
scp ubuntu@<ip>:~/work/manifest/evocargo.parquet data/manifest/

cd infra && tofu apply -var enable_data_vm=false   # машина и диск удаляются
```

Машина прерываемая: 8 vCPU и 16 ГБ обходятся в 4,15 руб в час (0,35 за vCPU·час и 0,0845
за ГБ RAM·час по прайсу на апрель 2026), плюс диск. Забыть её включённой неприятно, но не
смертельно; принудительный стоп раз в сутки заезду не мешает, потому что состояние лежит
в бакете, а не на диске.

## Запуск land

```bash
python -m data.land dawn --root /path/to/DAWN --limit 200   # проверка на выборке
python -m data.land dawn --root /path/to/DAWN               # полный проход
```

Пишет `manifest/<источник>.parquet` и печатает распределение меток, распределение
резкости и число дублей. Пиксели не перекодируются: читается только то, что нужно для
метаданных и метрик.

Правила разметки берутся из `labels` соответствующей записи `sources.yaml`. Пустой список
меток означает `clean`, а `__drop__` — что кадр вне таксономии и в манифест не идёт. Это
разные вещи: песчаная буря в DAWN не чистый кадр, и путать их нельзя.

## Запуск build

```bash
python -m data.build --recipe data/recipe.example.yaml \
                     --raw-root /path/to/bucket-root --dry-run   # калибровка и план
python -m data.build --recipe data/recipe.example.yaml \
                     --raw-root /path/to/bucket-root             # запись шардов
```

`--raw-root` — корень, повторяющий раскладку бакета: внутри должен лежать
каталог `raw/`, потому что ключи в `sources.yaml` это ключи объектов S3.

Приводит кадры к общему знаменателю тремя шагами, каждый убирает признак, по
которому источник узнаётся без взгляда на помеху:

| шаг | что убирает |
|---|---|
| квадрат `size x size`, кроп по центру | разрешение и соотношение сторон |
| единый кодек и качество | вес файла, он же детальность кодирования |
| приведение резкости к самому мягкому | различие оптики и обработки |

Проверено на реальных кадрах: разброс медианной резкости между источниками упал
со 150 до 2, вес файла — с «1.5 МБ против 0.27 МБ» до «45 против 34 КБ».

Дополнение полями вместо кропа намеренно не поддержано: толщина полос кодирует
исходное соотношение сторон, то есть возвращает ровно тот признак, ради
устранения которого всё делается.

Выравнивание резкости необратимо огрубляет данные, включается флагом
`target.equalize_sharpness`. Если в датасете появится класс `blur_motion`, его
надо выключить: иначе уничтожается тот самый сигнал, который нужно распознавать.

### Сырьё не трогается никогда

`raw/` открыт только на чтение. Стадия получает хранилище с единственным
разрешённым префиксом записи — `curated/<имя>-<хеш рецепта>/`, — и попытка
записать что-либо вне его поднимает `WriteOutsideAllowedPrefix`, а не пишет с
предупреждением.

Причина прозаическая: заезд стоил времени и трафика, а испорченный архив
восстанавливается только повторным скачиванием. У SID это Globus с ручными
шагами в вебе.

Новый датасет всегда собирается рядом, а не поверх: версия называется по хешу
рецепта, поэтому два разных рецепта дают два разных каталога и не могут
затереть друг друга.

### Отбор и сплиты идут по таблице

[`plan.py`](plan.py) решает, что попадёт в датасет, до всякого чтения картинок:
фильтр, прореживание, снятие точных дублей по `phash`, потолок на группу,
раздача выборок. На десяти тысячах строк это миллисекунды, а решение стоит
дороже всей остальной обработки.

Сплиты раздаются **целыми сиквенсами**. Метка, у которой меньше двух
независимых источников, не попадает в `val` и `test` вовсе: оценка на ней
мерила бы узнавание датасета, а не помехи. Если после этого `val` оказывается
пустым, стадия говорит об этом прямо — это состояние данных, а не сбой сборки,
и лечится вторым источником, а не правкой кода.

### Новый источник без единой строки кода

Стадия не знает про конкретные датасеты. Чтобы добавить источник, достаточно
описать в `sources.yaml`, как добраться до его байт:

```yaml
raw_storage:
  kind: zip                       # zip | tar | plain
  key: raw/foo/archive.zip
# либо, если архивов несколько:
  kind: tar
  key_by_prefix: { train: raw/foo/train.tar, val: raw/foo/val.tar }
# либо, если объекты лежат по одному:
  kind: plain
  prefix: raw/foo/
```

Остальное — метки, правила отбора, целевой формат — берётся из тех же
`sources.yaml` и рецепта.

## Реестр источников

[`sources.yaml`](sources.yaml) — единственное место, которое знает, откуда берутся байты
и на каких условиях. Каждая запись описывает доставку, лицензию и то, как метки источника
ложатся на общую таксономию.

Проект учебный, поэтому лицензии использование не ограничивают. Единственное следствие:
собранный датасет не выкладывается публично.

## Манифест

Схема задана явно в `land.py` и одинакова для всех источников — иначе манифесты не
склеиваются.

```
frame_uid        стабильный id, sha1(source|raw_path)[:16]
source           ключ из sources.yaml
source_version   snapshot источника
sequence_id      сиквенс внутри источника; при отсутствии — каталог кадра
raw_path         путь относительно корня источника
camera_type      front | fisheye_surround | unknown
labels           список меток; пустой список означает clean
width height     пиксели оригинала
bytes format
sharpness        дисперсия лапласиана
luma_mean        средняя яркость
luma_p01 luma_p99  клиппинг в тенях и светах
phash            64-битный перцептивный хеш для дедупликации
error            причина, по которой файл не прочитался
```

Метрики считаются на копии, приведённой к общей высоте 256. Без этой нормировки дисперсия
лапласиана несравнима между источниками разного разрешения, и 720p с 1080p окажутся в
разных классах резкости ни за что.

`camera_type` обязателен из-за WoodScape: там камеры кругового обзора, и без флага модель
выучит fisheye-виньетирование как признак грязи.

## Рецепт

[`recipe.example.yaml`](recipe.example.yaml) описывает целевые параметры, отбор, баланс и
сплиты. Пара «рецепт + снапшоты источников» однозначно определяет выход: тот же рецепт на
тех же `raw` даёт побайтово тот же датасет. Версия `curated` называется по хешу рецепта.

## Сплиты

Только по `sequence_id`, никогда по кадрам. При 20 Гц соседние кадры почти идентичны, и
случайный сплит по кадрам кладёт в тест почти те же изображения, что в трейн — метрики
получаются завышенными на десятки процентов, а на реальных данных модель разваливается.

Если у источника есть авторское деление, оно уважается: у SID 20 сиквенсов в train и
7 в test, ломать это без причины нельзя — иначе результаты не сравнить с публикацией.

## Что дальше

Порядок работы: заполнить `sources.yaml`, прогнать `land` по каждому источнику, посмотреть
на объединённый манифест, и только потом писать рецепт. Целевое разрешение и правила
отбора выбираются по фактическим распределениям, а не заранее.

Ноутбук [`snow_to_drive.ipynb`](snow_to_drive.ipynb) остался от варианта с Google Drive и
Colab. Логика перепаковки в нём рабочая и переиспользуется в `build`, но целевая площадка
теперь Yandex Cloud, а не Drive.
